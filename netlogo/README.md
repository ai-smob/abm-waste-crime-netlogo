# NetLogo port

`waste_crime.nlogox` is a NetLogo 7 port of the Python prototype, model version 0.2. It
reads the same parameter values and scenarios as the Python model from the CSV files in
`data/`, runs the same monthly loop in the same order, and reports the same metrics.

## Running it

**In NetLogo (7.0 or later).** Open `waste_crime.nlogox`. Choose a scenario and a seed,
press *setup*, then *go* or *run to end*. The plot shows the share of waste handled
illegally per month. The interface is deliberately minimal: the model has no spatial
component, so the view is unused.

**Headless, from the terminal.** The BehaviorSpace experiments are stored in the model:

| Experiment | What it runs |
| --- | --- |
| `smoke` | baseline, seed 1, one run |
| `regression` | every scenario, seeds 1 to 30, final metrics only (240 runs) |
| `timeseries` | the same, with metrics every month |
| `deep-check` | baseline and higher sanctions, seeds 1 to 100 (used to settle borderline comparisons) |

On a laptop with 8 threads the `regression` experiment took about 4 minutes; the Python
model runs the same 240 runs in about 16 seconds.

```
cd netlogo
bash "/path/to/NetLogo 7.0.4/netlogo-headless.sh" --model waste_crime.nlogox \
     --experiment regression --table results/netlogo_runs.csv --threads 4
```

Java 17 or later is needed. The repository's `tools/run_regression.sh` runs the
regression experiment and the comparison with the Python model in one go; the GitHub
Actions workflow does the same on every push.

## Shared data

| File | Content | Generated by |
| --- | --- | --- |
| `data/parameters.csv` | Every parameter as `key,type,value`, dotted keys, lists with an index | `scripts/export_netlogo_data.py` in the Python project, from `config/parametrar.yaml` |
| `data/scenarios.csv` | Every scenario's changes as `scenario,key,type,value` | the same script, from `config/scenarier.yaml` |

No value is typed in the NetLogo code. The Python project's test suite checks that these
files match its configuration, so a changed value in the YAML fails the tests until the
export is rerun. The labels of every value (source, derived, placeholder, assumption) are in
the Python project's parameter catalogue and in the model notes; the CSV carries only the
values.

## How the port follows the Python model

| Python (`wastecrime_abm/`) | NetLogo |
| --- | --- |
| `Producer`, `Company`, `Controller`, `Regulator` dataclasses | breeds `producers`, `companies`, `controllers`, `regulators`, all hidden turtles |
| `IllegalBatch` list (the hidden ground truth) | breed `batches`; each company keeps a list of the batches an inspection can still find |
| `Report`, `PendingStart` | lists of lists in the globals `reports` and `pending` |
| `model.step()`: the nine monthly sub-steps | `go`: the same nine procedures in the same order |
| `decision.py`: `risk_term`, `utility`, `choice_probabilities` | `pathway-utility`, `choice-probabilities`, `pick-choice` |
| `apply_changes` at the intervention month | the scenario's changes written into the parameter table at the same month |
| `outputs.summarize_run` | the `to-report` metrics at the end of the code, same definitions |
| `numpy.random.default_rng(seed)` | `random-seed run-seed` |

Deliberate correspondences worth knowing when reading the code:

- The decision is made per customer arrangement, revisited with probability
  `decision.reconsider_probability_per_month` each month and always after a finding, as in
  Python.
- Money terms are shares of the legal cost of the consignment; the formula and the
  multinomial-logit extension to two illegal options are identical.
- Supervision: complaints first, then a weighted draw without replacement among the
  rest (`rnd:weighted-n-of-list`), with the same risk score.
- Vicarious learning is applied once per other active firm in the municipality, as the
  Python loop does, so a decision-maker with two firms there is updated twice.
- A firm closed earlier in the month gets no further roadside findings.
- `detected-share` leaves out batches from the last `supervision.lookback_months` months,
  as the Python metric does.

## What cannot be identical

The two implementations use different random number generators (PCG64 in NumPy,
Mersenne Twister in NetLogo), and the order in which agents are processed differs
(`ask` is random order; Python iterates in creation order). The same seed therefore does
not give the same run. Equality is checked statistically over the 30 seeds per scenario,
see `tools/compare.py` and the comparison report it writes.

## Not ported

The web interface, login, experiment handling, parameter sweeps, the AI summary, the
animation and the charts stay in Python. The sensitivity analysis can be reproduced with a
BehaviorSpace experiment that varies a parameter, but the parameter table is loaded from
the CSV at setup, so a sweep would set the value after `setup` with
`table:put P "key" value` in the experiment's setup commands.
